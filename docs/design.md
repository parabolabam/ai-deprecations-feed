# Лента депрекаций AI-провайдеров — дизайн

Дата: 2026-11-22. Статус: на утверждении.

## Зачем

Нужна RSS-лента для чтения, в которую попадают анонсы о депрекациях и отключениях моделей и API у AI-провайдеров. Официальной подписки на страницу депрекаций OpenAI нет. Сторонний сервис `deprecations.info` на 20.11.2026 не содержит ни одной записи OpenAI и AWS Bedrock, хотя заявляет их в списке источников, и никак об этом не сообщает.

Результат нужен быстро. Лента — первый шаг, дальше сервис будет расширяться.

## Цели

- RSS- и JSON-лента анонсов по девяти источникам: OpenAI, Anthropic, Google AI (Gemini), Google Vertex AI, AWS Bedrock, Cohere, Groq, xAI, Azure AI Foundry.
- Ежедневное автоматическое обновление без собственного сервера.
- Поломка парсера видна сразу и не приводит к потере анонсов.
- Архив анонсов пригоден для будущих расширений.

## Чего не делаем сейчас

- Извлечение через LLM и упаковка в Docker.
- Алерты «до отключения N дней» и фильтр по используемым моделям.
- Сайт с таблицей и поиском.

## Чего нельзя допустить

- Источник молча перестал отдавать данные, а лента выглядит здоровой.
- Сбой парсера стёр уже накопленные записи.
- Репозиторий неограниченно растёт.

## Ограничения

- Личный публичный репозиторий на GitHub. На бесплатном плане GitHub Pages доступен только для публичных репозиториев.
- В публичном репозитории расписание Actions отключается после 60 дней без активности.
- Запуск по расписанию выполняется только из ветки по умолчанию.
- В репозитории нет секретов: все источники — публичные страницы.

## Рассмотренные подходы

1. **Форк `deprecations/deprecations-rss` (MIT).** Быстрый старт, но чужая модель «одна запись на модель» теряет анонсы про эндпоинты и фичи, а тихие поломки парсеров остаются. Отклонён.
2. **Свой сервис с парсером на каждый источник.** Чистые структурированные записи, но парсеры нужно писать и чинить.
3. **Лента из диффов без парсеров.** Почти не ломается, но записи сырые и шумные.
4. **Извлечение через LLM.** Устойчивее всего к смене вёрстки, но требует API-ключ и разворачивания в Docker. Отложен решением владельца.

**Выбрано: подход 2 с подходом 3 в роли страховки.** Извлечение оформляется сменным модулем, чтобы подход 4 позже добавлялся без переделки остального.

## Как это работает

Раз в сутки GitHub Actions для каждого источника:

1. Скачивает страницу и нормализует её в текст.
2. Сравнивает с прошлым снимком. Если изменений нет, источник пропускается.
3. Запускает экстрактор источника: парсер либо, если парсера ещё нет, генератор диффа.
4. Проверяет результат на правдоподобие.
5. Сливает новые записи с архивом, пересобирает ленты и публикует их на GitHub Pages.

### Единица данных — анонс

Поля анонса: источник, дата анонса, заголовок, список затронутых объектов (модели, эндпоинты, фичи), дата отключения, рекомендуемая замена, ссылка на страницу, дата первого наблюдения. Запись сырого диффа — тот же анонс с пометкой `raw` и текстом добавленных строк.

### Защита от поломок

- Ноль записей, падение их числа больше чем наполовину или запись без даты считаются сбоем парсера.
- При сбое старые записи источника сохраняются, изменение страницы попадает в ленту сырым диффом, добавляется запись «парсер источника X сломан» и автоматически открывается issue.
- Парсеры по возможности читают стабильный формат (для OpenAI — `.md`-версию страницы) и ищут таблицы по тексту заголовков, а не по вёрстке.
- Каждый парсер покрыт тестами на сохранённых снимках страниц.

## Хранение данных

| Данные | Срок |
|---|---|
| Снимки страниц | только последний на источник |
| Анонсы | бессрочно, в архивном JSON |
| Записи в RSS и JSON-ленте | за последние 6 месяцев |
| Сырые диффы | 90 дней |
| Статус источников | только текущее состояние |

- Код живёт в `main`, данные — в отдельной ветке `data`.
- Коммит в `data` делается только при изменениях.
- Раз в месяц история ветки `data` схлопывается в один коммит. Полная история снимков страниц не нужна.
- Раз в неделю делается служебный коммит с обновлением статуса, чтобы расписание не отключилось.

## Этапы

1. **Каркас, OpenAI и диффы для всех.** Парсер OpenAI, генератор диффов для остальных восьми источников, ленты, публикация, проверки и issue при сбое.
2. **Парсеры по одному.** Источники переводятся с диффов на парсеры в порядке, который задаст владелец.

## Технические решения исполнителя

Это решения исполнителя, владелец может их изменить.

- Python.
- GitHub Actions по расписанию раз в сутки и ручной запуск.
- GitHub Pages для раздачи `feed.xml`, `feed.json` и архивного `deprecations.json`.
- Состояние хранится файлами, без базы данных.

## Что остаётся исполнителю

- Точные URL и формат источника для каждого из восьми провайдеров, кроме OpenAI.
- Способ нормализации страниц перед сравнением, чтобы правки вёрстки не давали ложных диффов.
- Правило слияния анонсов при правке уже опубликованной записи.
- Имя репозитория и адрес ленты.
